# Executed exploratory predictor-native confidence comparison v1

**Completed locally; no new generation or change to the five frozen methods.** The new baseline recovers the original AlphaFold Server `ranking_score` for the legacy complexes and uses the existing Boltz 2.2.1 `confidence_score` for 3P0G. It is separately versioned and explicitly exploratory: candidate DockQ outcomes were already known before definition. Its protocol, code, nine synthetic tests, provenance and input/outcome bindings were frozen in local commit `4375c48` before selection and evaluation. Freeze SHA-256: `52b7641c9922adc42eb1761a02212a1049687e8e3605f07c1997ba12e01e6163`.

[COMPARISON.md](COMPARISON.md) is the single complete 24-row table: all five unchanged methods plus the new baseline, for all four complexes. [evaluation/comparison.csv](evaluation/comparison.csv) contains full-precision values and candidate IDs. JSON additionally retains all 40 attempt records, all 35 outcomes, within-job selections, ties and coverage. All five missing 5JQH seed-2 records remain missing.

## Predictor and confidence provenance

Every one of the 25 legacy coordinate/confidence pairs was checked against its original member in the three preserved GPCR verification archives, the historical reviewed coordinate hash, and the earlier confidence audit receipt. All six original requests were checked against the repository originals; each declares `dialect: alphafoldserver`, the appropriate name/seed and matching target settings across seeds. Protein order and explicit receptor/VHH chain maps are unchanged. The output mmCIF files identify `AlphaFold`, cite the AlphaFold 3 paper, and carry `AlphaFold-beta-20231127` software labels. All exact UUID/timestamp strings are retained per candidate and per job in provenance.json; 4MQS and 5C1M include September 2026 exports and 5JQH June 2026 exports. These are exported software labels, not recoverable proprietary weight checksums.

The request schema says `version: 3`; that is not evidence of the model release number. The current developer server-format README describes version 1, so this analysis does not claim the historical requests can be rerun unchanged on today's server. The conjunction of original requests, output metadata, archive associations and earlier hashes supports the originating predictor and exported field. It is not provider-signed attestation. For Boltz, the ten confidence/coordinate bindings and preserved successful generation/runtime receipts are retained; the existing field and its selections reproduce exactly.

The [developer output documentation](https://github.com/google-deepmind/alphafold3/blob/e68269f0ee4ddce2d2ffee48f36ba0c5bf39a851/docs/output.md) specifies whole-complex `ranking_score` as higher-better. It includes confidence, disorder and clash terms; its range differs from Boltz's. The [developer server-input guide](https://github.com/google-deepmind/alphafold/blob/c77e5d2a8961d1a353632c462914ff0a32a950f6/server/README.md) documents the export's request structure. The [server output guide](https://www.ebi.ac.uk/training/online/courses/alphafold/alphafold-3-and-alphafold-server/alphafold-server-your-gateway-to-alphafold-3/interpreting-results-from-alphafold-server/) documents paired filenames with model 0 first-ranked. The [Boltz 2.2.1 documentation](https://github.com/jwohlwend/boltz/blob/v2.2.1/docs/prediction.md) identifies its confidence_score and higher-better direction. Source scope and limitations are recorded in primary-documentation.json. No metric is recomputed from rounded components or substituted for the original field.

## What can be reproduced within a server job

All five available legacy jobs have five paired outputs with nonincreasing ranking_score by documented file rank. Their model-0 files belong to the exported maximum sets. Thus the documented server-selected file can be recovered, and the exported-score preference agrees with it.

However, the scalar values alone recover a unique maximum in only **one** job: 4MQS seed 2. Four jobs have tied exported maxima: 4MQS seed 1 (two), 5C1M seed 1 (four), 5C1M seed 2 (three), and 5JQH seed 1 (three). Unrounded scores/internal tie-breaking are absent. The baseline therefore preserves every tied ID and uses a uniform mean of their DockQ values; this is a reporting convention, not the server's observed tie-break. Documented model-0 DockQ values are separately retained in the withinJob records. 5JQH seed 2 has neither its coordinate nor confidence files in the archives, so its native selection cannot be recovered.

Pooling two jobs for a given target is the explicitly frozen retrospective study convention inherited from PR #60's candidate roster. It is not a server UI selection across separate jobs. Request sequences/settings match across seeds, but server execution labels are still retained without asserting identical hidden checkpoints. Confidence numbers are never combined across complexes or predictors.

## Results and limits

The new pooled baseline selects seed2_model_0 for Boltz 3P0G (DockQ 0.484628809, the best available). For AlphaFold Server it selects three tied candidates on 4MQS (mean 0.762448125; best 0.807119815), seven on 5C1M (mean 0.713463171; best 0.721171288), and three on 5JQH (mean 0.082895282; best 0.093139320). Full IDs, individual outcome ranges and signed gaps appear in the combined table. Best-available IDs are unique in these retained pools; score ties are not silently collapsed.

All five original methods retain their original selections and three legacy confidence abstentions. The original 3P0G negative result remains: frozen ConfoVHH selects DockQ 0.176256482. On 4MQS both graded variants (0.738287077) lose to this native-score baseline as well as burial alone; on 5JQH they select 0.093139320 compared with the native-score tie mean 0.082895282. Every win, loss and tie is retained without a global superiority claim.

These four complexes were exposed development cases. 3P0G, 5C1M and 5JQH share one pre-existing provisional relatedness component; 4MQS lies in another. There are zero certified independent validation groups. The legacy requests allowed templates, predictor-training membership is unresolved, and the two workflows and score definitions differ. This is not an independent comparison of predictor quality or evidence that their confidence scales are interchangeable.

## Runtime, verification and reuse

Selection and outcome joining took **0.079434 seconds** of local wall time under a 300-second limit. Provenance verification took about 1.2 seconds. DockQ and geometry were reused from the verified preceding execution, not recalculated or relabeled. GPU time and new cloud charges were zero.

Nine synthetic tests passed: exact decimal ties, precision preservation, distinct score ranges, invalid/absent fields, no metric substitution, coordinate missingness, whole-pool abstention, missing-outcome bounds and tamper/duplicate-key rejection. An independent calculation from the raw confidence JSON reproduced all four selected sets and their means. Every original method row, abstention and preserved outcome agrees with PR #60. The prior evidence verifier and the new freeze verifier pass.

With the existing evaluation Python environment, run the frozen script's `select` command against the preserved successful retrospective bundle, then `evaluate` against the saved selection directory, using fresh output paths. `audit` can separately reverify the original three archives. The source, protocol, test file, provenance, receipts and tables are additive files; no original evaluator or ranking file was edited.
